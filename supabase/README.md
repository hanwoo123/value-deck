# 거래글 저장 연결

## 프로젝트 운영자가 한 번 수행할 설정

1. Supabase 프로젝트 `xmdmwchfbroitizgtmlo`의 **SQL Editor → New query**를 엽니다.
2. `migrations/202611020001_trade_board.sql`의 전체 내용을 붙여넣어 **Run** 합니다. 파일은 테이블 생성과 RLS 권한을 함께 적용하며, 재실행 가능합니다. 테이블은 비워서 시작합니다. 기존 거래 데이터를 삭제하지 않습니다.
3. **Authentication → Sign In / Providers → Anonymous Sign-Ins**를 켜고 저장합니다. 이는 방문자에게 로그인 화면을 요구하는 기능이 아니라, 자신이 작성한 글을 구분하는 내부 식별자입니다. 테스트 사용자나 가짜 Roblox 인증을 만들지 않습니다.
4. 사이트 `#/trades`에서 닉네임을 저장하고 거래글 하나를 등록합니다. 다른 브라우저에서도 글이 보이는지 확인하고, 작성 브라우저에서 완료 처리하세요. SQL과 익명 인증 설정은 공개 키로 변경할 수 없으므로 프로젝트 소유자가 수행해야 합니다.

현재 클라우드에서 실제 프로젝트 응답까지 검증하려면 환경 설정에 `xmdmwchfbroitizgtmlo.supabase.co`의 HTTPS 접근도 적용되어 있어야 합니다. 공개 사이트 방문자의 네트워크 정책과는 별개입니다.

## 공개 키와 권한

`js/trade-config.js`는 공개 URL과 publishable key만 포함합니다. 비밀번호, secret key, service_role 키, 개인 access token은 프런트엔드나 저장소에 넣지 않습니다. GitHub와 Supabase의 저장소 통합은 필수가 아닙니다.

RLS 정책과 열별 권한으로 다음을 보장합니다.

- 로그인 전에는 진행 중인 글만 읽습니다. 글 작성 시 공식 Supabase SDK가 익명 세션을 만들고 보관합니다.
- 작성자의 UUID·글 ID·작성 시각·상태는 DB가 지정합니다. 다른 사용자의 ID를 넣어 글을 만들 수 없습니다.
- 본인 글의 상태만 `open`에서 `completed`로 바꿀 수 있습니다. 이름·아이템·메모·작성자 조작, 직접 삭제는 허용하지 않습니다.
- 완료 글은 작성자 본인에게만 보입니다. 공개 목록에는 진행 글만 표시합니다.
- 알려진 블록스 프루츠 아이템 1~8개씩, 정수 수량 1~99, 사용자 이름 영문/숫자/밑줄 3~20자, 메모 200자 이내로 DB가 검사합니다.
- 작성자당 진행 글 최대 5개, 1분당 1개 등록 제한을 DB 트리거에서 처리합니다. 익명 세션 자체를 새로 만드는 행위를 완전히 막는 장치는 아니므로 공개 운영에서는 Supabase Auth의 가입 속도 제한·봇 방어 설정도 관리해야 합니다.

닉네임은 본인이 직접 적는 값이므로 실제 존재/소유 여부를 검증하지 않습니다. ‘인증됨’ 표시는 하지 않습니다. 글의 닉네임은 작성 시점 값이며, 닉네임 설정 변경은 다음 글에 적용됩니다. 실제 교환은 게임 안에서 합니다.

브라우저 데이터 삭제·다른 기기 접속 시 익명 작성자 권한을 복구하기 어렵습니다. 닉네임만 다시 입력한다고 다른 사용자의 글 관리 권한을 얻을 수는 없습니다. 계정 복구·관리자 신고/삭제 화면은 현재 범위에 포함하지 않습니다. 운영자는 Supabase 대시보드에서 필요 시 글을 관리할 수 있습니다.

## 검증

`npm ci && npm test`는 PostgreSQL 호환 PGlite에서 마이그레이션을 실행하고 anon/authenticated 역할의 RLS·작성자 권한·변조 방지·입력 제약·등록 제한을 검사합니다. 실제 프로젝트의 키/설정/네트워크 준비까지 증명하지는 않습니다.

공식 SDK `@supabase/supabase-js@2.57.4`를 `js/vendor`에 고정해 포함했습니다. 라이선스는 같은 폴더에 있습니다. 시세표·계산기는 계속 정적 파일로 실행되며 Node 서버는 필요 없습니다.
